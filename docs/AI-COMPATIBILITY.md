# AI 请求和失败恢复

1.4.1 修复用户报告的 DeepSeek `TimeoutException after 0:01:30`：原先一次非流式请求固定在 90 秒中断。现在优先请求 Chat Completions SSE，接受 keep-alive、UTF-8 分段、最终文本和结束标记；同时接受普通 JSON。接口明确拒绝 stream 参数时，仅回退一次非流式请求。

每次请求的总等待上限为 5 分钟，超时会关闭连接。原始文件批次发生超时、上下文过长或输出被截断时，在完整物料组之间拆半重试。单个物料组仍过大时保留明确错误，用户可以调整设置或复核该组。推理内容不作为最终核对结论；流中断或输出截断不计为已完成。

“重试未完成批次”保留成功结果，从第一个未完成批次继续，重新确认当前接收地址及范围。重新导入、修改规则或清空会使旧批次失效。新设置默认 24000 字符；已有上限保留，大文件建议 12000 或 24000。

协议依据：[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。自动验证使用合成数据和本机 HTTP 服务；超过 90 秒的响应采用虚拟时间验证，没有用真实 API Key 调用第三方服务。真实参考文件只在本机验证原文提取和批次完整性，不上传到测试服务或公开仓库。
